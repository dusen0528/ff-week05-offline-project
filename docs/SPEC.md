# 요구사항 명세 (SPEC)

> 상태: **v0.2**. 1차 자료(요구사항 Excel, 출력 예시 Excel, 샘플컴퍼니 2024·2025 PDF)를 읽고 구체화했습니다. 2026-11-21 기준입니다.
> 결정의 근거는 [DECISIONS.md](DECISIONS.md) `D-xxx`, 고객 질문은 [QUESTIONS.md](QUESTIONS.md) `Q-xx`, 값과 페이지는 [FORM_MAP.md](FORM_MAP.md)에 있습니다.
> **v0.3 (2026-11-21, 고객 답변 Q-01~Q-03 반영)**: 보고서 구성이 **I.기본정보 / II.표준재무제표 / III.법인세 신고상황 / IV.이월결손금 / V.소득금액조정 / VI.공제·감면세액 / VII.요약 코멘트 / VIII.재무제표 주요 특이사항**으로 확정됐습니다 (D-019). 아래 §5 표는 v0.2 기준이므로 섹션 구성은 D-019를 따릅니다. 금액 출처는 표준재무제표(D-020), 요약 카드 단위는 D-021, 증감 표기는 D-022입니다.
> 표기: ✅ 확정 · ⏳ 잠정(고객 확인 전, 보고서에는 «확인 필요»)

---

## 1. 배경과 목적

| 구분 | 내용 |
|---|---|
| 고객 | 세무법인. 보고서 발행 주체는 「**샘플세무법인**」입니다 (요구사항 #8) |
| 문제 | 신고 시즌에 직원 1명이 법인을 최대 20개까지 맡습니다. 자료 식별, 수치 추출, 비교표 작성이 반복됩니다. |
| 목적 | 반복 작업은 프로그램이 하고, 판단(모호한 기준, 세무 판단, 최종 검토)은 사람이 합니다. |
| 성공 기준 | 보고서의 모든 숫자가 맞아야 합니다. 숫자마다 **파일 · 서식 · 페이지** 근거를 댈 수 있어야 합니다. |

## 2. 사용자
| 역할 | 하는 일 | 프로그램에 바라는 것 |
|---|---|---|
| 세무법인 실무자 | PDF를 올려 보고서와 청구서를 만들고 검토자에게 넘김 | 회사만 바꿔 반복 실행 |
| 담당 세무사 | 근거를 확인하고, 코멘트와 특이사항을 검토한 뒤 발송 | 근거 표, «확인 필요» 목록, 특이사항 후보 |

## 3. 입력과 출력

### 3.1 입력 (1차)
| ID | 파일 | 내용 |
|---|---|---|
| IN-1 | `샘플컴퍼니_2024_세무조정계산서.pdf` | 전기 (제1기). 48쪽, 텍스트 PDF |
| IN-2 | `샘플컴퍼니_2025_세무조정계산서.pdf` | 당기 (제2기). 66쪽, 텍스트 PDF |
| IN-3 | `요구사항.xlsx` | 보고서 #1~#8, 조정료청구서 #1~#7 (3~5번 빈칸) |
| IN-4 | `보고서_출력예시.xlsx` | 다른 회사(2021) 「법인세 신고 결과 보고서」 예시. 형식 참고용 (D-001) |

|---|---|:-:|---|

| OUT-2 | 같은 내용의 보고서 **Excel** (수식 포함, 수기 수정용) | — | 요구사항 전체 틀 #1·#2 (D-014) |

## 4. 처리 흐름

```
PDF ──▶ [01 접수] 사업자번호·사업연도 식별, 전기/당기 묶기 (D-002)
      ▶ [02 파싱] kordoc → Markdown/JSON (서식 탐색·근거 인용)
                  레이아웃 텍스트 → 숫자 추출 (D-016)
      ▶ [03 추출] 서식명·라벨로 값 찾기 → {값, 파일, 서식, 페이지, 라벨}
      ▶ [04 검산] 합계·등식·전기 열 대조, 이상 징후 탐지 (D-004 · D-012)
      ▶ [05 작성] 규칙(config) 적용 → 표·그래프·코멘트 → PDF/Excel
      ▶ [06 검토] «확인 필요» 목록 0개인지 확인 → 제출
```

## 6. 기능 요구사항

### FR-1 접수 · 식별 (D-002)
- FR-1.1 별지 제3호에서 법인명, 사업자등록번호, 사업연도를 읽습니다.
- FR-1.2 두 파일의 사업자번호가 다르면 중단합니다.
- FR-1.3 사업연도 시작일로 전기와 당기를 정합니다. 연속하지 않으면 경고합니다.
- FR-1.4 필요한 서식(FORM_MAP §3의 굵은 표시)이 없으면 «자료 누락»으로 기록하고 요청 목록을 만듭니다.

### FR-2 파싱 · 추출 (D-003 · D-016)
- FR-2.1 kordoc으로 Markdown과 JSON을 만듭니다. JSON 블록에는 `pageNumber`와 `bbox`가 있어 서식 위치 탐색과 근거 인용에 씁니다.
- FR-2.2 재무제표 숫자는 레이아웃 텍스트에서 「계정명 … 당기 금액 … 전기 금액」 줄을 파싱합니다.
- FR-2.3 금액은 결산 재무상태표·손익계산서를 1순위로 씁니다. 표준재무제표는 코드로 대조합니다.
- FR-2.4 값마다 `{항목, 연도, 값, 단위, 파일, 서식, 페이지, 원문 라벨, 상태}`를 저장합니다.

### FR-3 계산 규칙 (config/rules.yaml)
| 규칙 | 값 | 상태 |
|---|---|---|
| 증감액 | 당기 − 전기 | ✅ |
| 증감률 | (당기 − 전기) ÷ \|전기\| × 100. 부호가 바뀌면 흑자전환/적자전환/적자지속, 전기가 0이면 «신규» | ⏳ Q-03 |
| 부채비율 | 부채총계 ÷ 자본총계 × 100. 자본 ≤ 0이면 «자본잠식» | ✅ 공식 / ⏳ 표기 Q-02 |
| 영업외손익 | 영업외수익 − 영업외비용 | ✅ (D-010) |
| 매출 대비 비중 | 항목 ÷ 같은 연도 매출액 × 100 | ✅ (#5) |
| 판관비 구성비 | 항목 ÷ 같은 연도 판관비 합계 × 100 | ✅ (#2) |
| 주요 항목 선정 | 당기 금액 내림차순. 표 6개, 그래프 5개 | ⏳ Q-04 |
| 억원 환산 | 원 ÷ 100,000,000, 소수 2자리 반올림 | ⏳ Q-02 |
| 비율 표기 | % 소수 2자리 | ✅ (예시 Excel) |

### FR-4 검산 (D-004 · D-012)
- FR-4.1 자산 = 부채 + 자본
- FR-4.2 매출 − 매출원가 = 매출총이익, 매출총이익 − 판관비 = 영업손익
- FR-4.3 영업손익 + 영업외수익 − 영업외비용 = 세전손익, 세전손익 − 법인세등 = 당기순손익
- FR-4.4 판관비 세부 항목의 합 = 판관비 합계
- FR-4.5 당기 PDF의 전기 열 = 전기 PDF의 당기 값
- FR-4.6 결산서 당기순손익 = 별지 3호 ①01
- FR-4.7 세무상 결손금 = 별지 50호(갑) 결손금 발생액. **1차에서는 불일치입니다 (F-01)**
- FR-4.8 법인세등 = 법인세 차감납부세액 + 지방소득세 (2,417,443 + 302,180 = 2,719,623 ✅)
- 검산에 실패하면 해당 값을 «확인 필요»로 바꾸고 특이사항 후보에 올립니다.

### FR-5 코멘트 · 특이사항 생성
- FR-5.1 요약 코멘트는 수치를 끼워 넣는 템플릿 문장입니다. 숫자는 추출 값만 씁니다.
- FR-5.2 특이사항은 탐지 규칙(D-012)으로 후보를 만들고, 근거 페이지를 붙입니다. 무엇을 실을지는 config에서 고릅니다.

### FR-6 «확인 필요» 처리 (D-017)
- 규칙 값이 `null`이거나, 검산에 실패하거나, 고객 답변이 없으면 «확인 필요»입니다.
- 실행이 끝나면 목록을 출력합니다. **0개가 아니면 제출하지 않습니다.**

### FR-7 조정료청구서 (D-015)
- 기준 금액 = max(매출액, 자산총계 × 1/2) ⏳ (해석은 Q-09)
  - 2025 값: max(192,734,983, 31,105,224) = 192,734,983
- 요율, 가산율, 양식은 자료를 받기 전까지 «확인 필요»입니다.
- CMS 출금일과 피드백 요청일은 설정값으로 둡니다 (관리자가 지정).

## 9. 채점 기준 요약
- 채점 대상은 보고서 PDF 1개입니다.
- 필수 항목을 모두 맞히고, 전체에서 정해진 개수 이상을 맞히면 통과입니다.
- 필수 항목은 R-1 주요 지표 4개일 가능성이 높습니다.
- 재제출은 2분 뒤에 가능합니다. 피드백은 [ROUNDS.md](ROUNDS.md)에 기록합니다.

| 예상 변화 | 대비 |
